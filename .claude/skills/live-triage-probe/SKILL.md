# live-triage-probe

A step between `mock-triage` and the real `/intake-triage`.

`mock-triage` proves the plumbing — spawn, stream parsing, structured output,
sink — but it reads nothing, so the caller disables the MCP gate and passes an
empty tool allowlist. That leaves the two riskiest parts of the pipeline
untested: **the Atlassian MCP session** and **the tool allowlist**.

This skill reads one real ticket and nothing else. It is not a triage. Its
verdict is derived mechanically from what the ticket contains, so the run stays
cheap and the output stays assertable.

## Usage

```
/live-triage-probe SSX-3812
/live-triage-probe SSX-3812 --no-write
```

`--no-write` is accepted and echoed. It changes nothing: this skill never
writes under any circumstances.

## Behaviour

1. Fetch the issue with `getJiraIssue` (cloudId `storebrand.atlassian.net`,
   fields `summary`, `description`, `issuetype`, `status`, `created`).
   Do not call any other tool. Do not search for duplicates — that is the real
   skill's job and it is what makes the real skill expensive.
2. Derive the verdict from the fetched content only:

   | Condition (first match wins)                 | verdict        | labels                   |
   | -------------------------------------------- | -------------- | ------------------------ |
   | Issue type is `Deloppgave`                   | `not-our-team` | `route:other-team`       |
   | Description missing, or under 200 characters | `needs-info`   | `dor:gaps`, `route:ours` |
   | Otherwise                                    | `ready-ish`    | `dor:pass`, `route:ours` |

   This is a proxy for description quality, not a judgement about the ticket.

3. Set `recommendedNextStep` to one sentence naming the concrete gap observed.

4. Set `report` to markdown of roughly this shape:

```markdown
## LIVE PROBE — not a real triage

**Issue:** <KEY> — <the real summary, as fetched>
**Type:** <type> · **Status:** <status> · **Created:** <created, verbatim>
**Description length:** <n> characters
**Flags:** <--no-write, or "none">

### Verdict

<verdict> — <the rule from the table that fired>

### Why

Generated by the live-triage-probe test double. The ticket was genuinely read
over the Atlassian MCP, but no duplicate search and no knowledge-vault lookup
were performed. Do not act on this.
```

## Constraints

- **Read exactly one issue.** No `searchJiraIssuesUsingJql`, no Confluence, no
  filesystem. If the allowlist denies a tool, stop and fail — a denial is a
  real result the caller needs to see, not something to work around.
- **Never write** to Jira, Confluence, Slack or disk. No comments, no labels,
  no transitions.
- Report the `created` timestamp **verbatim**, including its offset. The caller
  needs to see the real format rather than a normalised one.
- Always emit output conforming to the caller's JSON schema. The `report` field
  must begin with the literal string `## LIVE PROBE` so a probe result can
  never be mistaken for a real triage downstream.
